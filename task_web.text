# 🌐 WEB PLATFORM — admin website + player website (redeem codes, buy gems and items)

## How it fits together (read first)

- One Firebase project for everything: the game, the player website and the admin website share the same accounts
  (Firebase Auth) and database (Firestore). A player signs in on the website with the email/password they linked in the game.
- The website never edits a player's save. Gems live in the save on the phone, and the phone's newer save would overwrite any
  web change. Instead, the server leaves a "grant" (a reward waiting to be collected) in the player's inbox, and the game
  collects it. Web purchases, redeem codes and admin gifts all arrive this way.
- Only server code (Cloud Functions, using the Firebase Admin SDK) may create grants, orders and codes. The browser and the
  game are never trusted to do it.
- Build order: WEB 0 → WEB 1 (game side) → WEB 2 → WEB 3 → WEB 5 → WEB 4 (shop, with money) → WEB 6 → WEB 7.
