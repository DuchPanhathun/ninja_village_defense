# Core Gameplay

Instead of controlling attacks manually,

The player only controls movement.

The ninja automatically attacks the nearest enemy.

This keeps gameplay simple enough for one-handed mobile play.

Example:

```
            Goblin

      Goblin      Goblin

            YOU

         ↓ Move

Auto throws shuriken
```

Every 30 seconds:

```
LEVEL UP!

Choose ONE

🌀 Clone Jutsu
🔥 Fire Shuriken
⚡ Attack Speed +20%
```

Exactly like a roguelike.

# Boss Design

Every boss should introduce a memorable mechanic.

### Giant Oni

- Charges across the map.
- Smashes the ground to create shockwaves.

### Spider Queen

- Fills the arena with webs that slow movement.
- Spawns spiderlings continuously.

### Shadow Ninja

- Mirrors the player's movements.
- Uses the same weapon and abilities as the player.

### Nine-Tailed Fox

- Teleports between positions.
- Creates illusion clones that explode.

# Monetization (Player-Friendly)

A sustainable free-to-play model can include:

- Cosmetic ninja skins
- Seasonal battle pass
- Optional ad to revive once per run or double rewards
- Starter bundles
- Premium pets or cosmetics
- Daily and weekly events

Avoid making purchases mandatory to progress.

# Development Roadmap

## Phase 1 (1–2 months): Prototype

Focus on proving the gameplay is fun.

- One playable map
- One ninja
- Auto-attack
- Movement controls
- One enemy type
- One boss
- Ten upgrade choices
- Basic leveling
- One weapon
- Health and damage systems

**Goal:** Players should enjoy a 10-minute run.

---

## Phase 2 (2–3 months): Vertical Slice

Build a polished demo.

- Three maps
- Five enemy types
- Three bosses
- Twenty skills
- Five skill evolutions
- Basic village screen
- Weapon upgrades
- Save/load system
- Sound effects and UI polish

**Goal:** A polished build suitable for playtesting.

---

## Phase 3 (2–4 months): Soft Launch

Add long-term progression.

- Hero roster
- Pets
- Talent tree
- Village buildings
- Daily missions
- Achievements
- Basic analytics
- Cloud save
- Ads and in-app purchases

**Goal:** Release in one region to gather player feedback.

---

## Phase 4: Global Launch

Expand content and retention.

- Seasonal events
- New maps and bosses
- Guilds or clans (optional)
- Leaderboards
- Additional heroes and pets
- New elemental combinations
- Continuous balance updates

## Suggested Unity Architecture

Since you're a software engineer, I'd recommend designing the project with modular systems from the beginning:

```
Game
├── Player System
├── Enemy System
├── Weapon System
├── Skill System
├── Element Combination System
├── AI System
├── Wave Manager
├── Boss System
├── Loot System
├── Village System
├── Economy System
├── Save System
├── Quest System
├── Audio Manager
├── UI Manager
└── Analytics Manager
```

Each system should communicate through events rather than direct dependencies where possible. This makes it much easier to add new heroes, skills, enemies, or game modes later.
